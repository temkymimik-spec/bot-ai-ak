# Telegram-бот лид-система (pocket-option) для bothost.ru

Полный цикл: партнёр лиет людей по индивидуальным ссылкам → они проходят **капчу** → получают контакт **ИИ-наставника** (твой Telegram-аккаунт) → ИИ греет их в твоём стиле → **жёсткая ИИ-фильтрация** отсеивает пустых и подтверждает только реальных лидов → партнёру начисляется 1 лид = 250 руб → вывод раз в неделю (сб–вс, от 4 лидов).

## Схема работы
```
Партнёр создаёт ссылку → https://t.me/<бот>?start=CODE
      │
      ▼  люди заходят
Бот: "Подпишись на 3 канала (защита от ботов)"  ← капча (каналы настраивает админ)
      │  прошёл проверку (бот проверяет подписку)
      ▼
Бот выдаёт @username ИИ-аккаунта + заносит лида в базу
      │  лид пишет аккаунту
      ▼
Telethon-воркер: ИИ отвечает в твоём стиле, греет к первому депозиту
      │  партнёр скидывает proof (pocket id, сколько заработал)
      ▼
ИИ жёстко скорит переписку + proof → если подтверждает (2+ раза, скор ≥0.75, есть proof)
      → партнёру +1 лид (250 руб)
```

## Стек
- **aiogram 3** — бот (админ + кабинет партнёра)
- **Telethon** — твой аккаунт, ИИ отвечает в его чатах (роботает асинхронно, очередь + rate-limit)
- **OpenRouter API** — генерация ответов и **жёсткая оценка лидов** (через aiohttp, асинхронно)

## Установка и запуск
```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполни
./venv/bin/python bot.py
```

`requirements.txt` теперь использует aiohttp вместо requests (асинхронно — для сотен диалогов).

## Настройка `.env`
```
BOT_TOKEN=...
ADMIN_IDS=1,2
OPENROUTER_API_KEY=...
API_ID=...            # my.telegram.org
API_HASH=...
AI_MODEL=openai/gpt-4o-mini
LID_RATE=250
MIN_WITHDRAW_LIDS=4
```

## Роли

### Админ (ты)
- Кидаешь `.session` файл аккаунта → подключается, ИИ начинает гресть
- `/пример` — задаёшь примеры общения, ИИ подражает
- `/канал <channel_id> [@user]` — добавляешь каналы для капчи (бот добавь админом в эти каналы → сможет проверять подписку)
- `ADMIN_IDS` — только твои id имеют доступ к админ-панели
- Панель: статистика, топ партнёров, все ссылки, капча-каналы, оценка чатов, заявки на вывод, перезапуск воркеров

### Партнёр (пользователь)
- `/start` → создаёт партнёрскую ссылку на выбранный аккаунт
- Льёт людей → те проходят капчу и получают ИИ-наставника
- Скидывает proof → ИИ подтверждает/отсеивает (см. жёсткую фильтрацию)
- Вывод: сб–вс, от 4 лидов, идёт в личку партнёра (кошелёк в заявке)

## Жёсткая фильтрация лидов (`ai.evaluate_chat`)
Лид подтверждается **только если ВСЕ** условия в `config.py`:
- `score >= SCORE_CONFIRM_THRESHOLD` (0.75) — средняя оценка ИИ по переписке
- `confirmations >= MIN_CONFIRMATIONS` (2) — интерес подтверждён несколько раз (не один пост)
- `needs_proof == False` — при `REQUIRE_PROOF=1` (по умолчанию) лид обязан прислать proof (pocket id + сколько заработал)

ИИ смотрит: задаёт ли вопросы по торговле/выводу, сделал ли депозит, активность НЕ односложная, есть ли pocket id. Односложные ответы, молчание, отсутствие proof → жёсткий reject.

## Асинхронность на сотни людей в день (`worker.py`)
- **Очередь исходящих сообщений** per аккаунт + `RATE_LIMIT_DELAY` — не спалим аккаунт
- `DAILY_REPLY_LIMIT` (300/день) — стоп-кран для защиты от бана
- **Тепло аккаунта** `WARM_UP_MSGS` — первые сообщения быстрые, потом ровный темп
- ИИ-генерация через одну общую `aiohttp`-сессию — параллельно, не блокирует поллинг
- История диалогов в SQLite (память на 40 последних сообщений)

## Структура
```
bot.py      — бот: админ-панель, капча, ссылки, proof, вывод
worker.py   — Telethon-воркер: очередь, rate-limit, ИИ-ответы
ai.py       — OpenRouter: грев + жёсткий скоринг лидов
database.py — SQLite
config.py   — настройки + пороги фильтрации
sessions/   — .session файлы аккаунтов
```

> ⚠️ Pocket-option — рискованный инструмент. Работа со сторонними Telegram-аккаунтами несёт риск бана: не перегревай аккаунты, используй `DAILY_REPLY_LIMIT` и `RATE_LIMIT_DELAY`.
