# Telegram-бот лид-система (pocket-option) для bothost.ru

Полный цикл: партнёр лиет людей по индивидуальным ссылкам → они проходят **капчу** → получают контакт **ИИ-наставника** (твой Telegram-аккаунт) → ИИ сам, по ходу переписки, расспрашивает про действие на pocket-option → как только человек реально сделал действие (депозит/сделка/pocket id) и ИИ это подтвердил (2+ раза) → **партнёру автоматически начисляется 1 лид = 250 руб**. Никаких proof от партнёра — всё на стороне ИИ. Вывод раз в неделю (сб–вс, от 4 лидов).

## Схема работы
```
Партнёр создаёт ссылку → https://t.me/<бот>?start=CODE  (на конкретный аккаунт)
      │
      ▼  люди заходят
Бот: капча (подпишись на 3 канала)  ← проверка подписки ботом
      │  прошёл проверку
      ▼
Бот выдаёт @username ИИ-аккаунта + заносит лида в базу на партнёра
      │  лид пишет аккаунту
      ▼
Telethon-воркер: ИИ отвечает В СТИЛЕ АККАУНТА, расспрашивает про pocket-option
      │  ИИ каждые N сообщений сам оценивает: сделал ли действие
      ▼
Есть РЕАЛЬНОЕ действие (депозит/сделка/pocket id, 2+ раза) → авто +1 лид партнёру (250 руб)
```

## Стек
- **aiogram 3** — бот (админ + кабинет партнёра)
- **Telethon** — твои аккаунты, ИИ отвечает в их чатах (асинхронно, очередь + rate-limit)
- **OpenRouter API** — генерация ответов и оценка лидов (через aiohttp)

## Установка и запуск
```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

## Роли

### Админ (ты)
- Кидаешь `.session` файл → аккаунт подключается, ИИ начинает гресть
- **🎛 Аккаунты**: список всех сессий, включить/пауза/удалить, статистика по каждому (ответы/день, начислено лидов), просмотр чатов аккаунта
- **`/пример`** — общий пример для всех аккаунтов
- **`/стиль <имя_сессии>`** или кнопка «Стиль аккаунта» — свой стиль под конкретный аккаунт (у каждого свой голос)
- **`/канал <id>`** — каналы для капчи (бот ставишь админом → проверяет подписку)
- Панель: статистика, топ партнёров, все ссылки, оценка чатов, заявки на вывод, перезапуск

### Партнёр (пользователь)
- `/start` → создаёт партнёрскую ссылку на нужный аккаунт
- Льёт людей → те проходят капчу и получают ИИ-наставника
- **Ничего не отправляет** — ИИ сам выясняет действие и начисляет лид
- Видит в статистике начисленные лиды; вывод: сб–вс, от 4 лидов

## Авто-начисление лида (критерий)
Лид начисляется автоматически, когда (`ai.evaluate_action` + воркер):
- ИИ зафиксировал **реальное действие** на pocket-option: депозит, сделка, или прислал **pocket id** / подтвердил пополнение
- Подтверждений действия >= `MIN_CONFIRMATIONS` (2) — человек не раз проявил действие
- При `REQUIRE_ACTION=1` (по умолчанию) без действия лид НЕ засчитывается
- Односложные ответы, молчание, "интересно" без действия → reject
- ИИ это делает сам в фоне по ходу диалога (каждые `EVAL_EVERY` сообщений) и начисляет БЕЗ участия партнёра

## Асинхронность на сотни людей в день (`worker.py`)
- **Очередь исходящих** per аккаунт + `RATE_LIMIT_DELAY` — не спалим
- `DAILY_REPLY_LIMIT` (300/день на аккаунт) — стоп-кран от бана
- `WARM_UP_MSGS` — тепло аккаунта
- Общая `aiohttp`-сессия для параллельной генерации ИИ, поллинг не блокируется
- История диалогов в SQLite (память 40 сообщений), под каждый аккаунт своя
- **Мульти-акк**: несколько `.session` одновременно, каждый со своим статусом/стилем

## Структура
```
bot.py      — бот: админ(+ аккаунты), капча, ссылки, вывод
worker.py   — мульти-акк Telethon-воркеры: очередь, rate-limit, ИИ-ответы, авто-начисление
ai.py       — OpenRouter: грев + оценка действия на pool-option
database.py — SQLite
config.py   — настройки и пороги
sessions/   — .session файлы аккаунтов
Dockerfile / docker-compose.yml — хостинг
```

> ⚠️ pocket-option — рискованный инструмент. Работа со сторонними Telegram-аккаунтами несёт риск бана: не перегревай аккаунты, используй `DAILY_REPLY_LIMIT` и `RATE_LIMIT_DELAY`.
